# Go Migration Platform 汇报大纲

## Audience
项目汇报对象主要是管理层、业务负责人和协同部门，重点是听懂“这个项目解决了什么问题、做成了什么能力、下一步还能怎么用”。

## Objective
把原本分散的业务入口、评估流程和管理配置，讲成一套清晰的业务闭环，突出项目价值而不是技术实现。

## Narrative Arc
1. 先讲项目价值：统一入口、统一流程、统一评估、统一监管。
2. 再讲痛点：多系统、多角色、多配置、手工多、效率低。
3. 再按板块介绍功能：总控后台、机构运营后台、评估 Pad、家长端、政府端。
4. 最后讲亮点：配置化、多端协同、专业评估闭环、结果可沉淀可复用。

## Slide List
1. 封面
2. 项目解决了哪些问题
3. 项目板块总览
4. 平台总控后台
5. 机构运营后台
6. 评估 Pad
7. 结果沉淀与共享
8. 项目亮点
9. 总结与下一步

## Source Plan
- 仅使用用户提供的真实项目截图。
- 重点截图包括总控后台配置页、机构后台首页与课表页、PEP-3 评估 Pad、评估报告列表、IEP 计划页。

## Visual System
- 整体风格：浅暖色背景、白色卡片、橙色主强调，辅以蓝绿紫用于区分板块。
- 图像呈现：截图以大图卡片或拼图方式呈现，保留界面真实感。
- 文案风格：短句、业务语言、少术语。

## Asset Needs
- 总控后台：登录页配置、机构开通、政府账号、云存储配置。
- 机构端：首页、课表板、排课/日程视图。
- 评估端：量表库、工作台、报告列表、IEP 计划。
- 封面：项目主页或评估工作台类截图。

## Editability Plan
- 标题、说明、要点、结论全部使用可编辑文本。
- 截图只作为视觉证据，不把关键信息做成图片文字。
- 每页保留简短结论句，方便现场讲述。
