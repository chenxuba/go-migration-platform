# VB-MAPP 智能测评证据记录设计

## 设计结论

VB-MAPP Pad 不能按普通量表做成“读题后选 0 / 0.5 / 1”。很多题的核心不是选择分数，而是记录可复核证据：孩子说了什么、做了什么、用了什么材料、是否自发、是否有辅助、是否满足计时和泛化条件。

因此产品形态应改为：

1. 每道题有独立 `responseSchema`，定义本题必须记录哪些证据。
2. 页面不手写 170 套，而是用记录器模板渲染，例如提要求事件记录器、听者反应试次记录器、LRFFC记录器、书写作品记录器。
3. 系统根据结构化证据自动统计指标并建议分数，老师最终确认或覆盖。
4. PDF、Word、IEP、历史对比不再只依赖分数，而是可以引用证据、素材、孩子原话和错误模式。

## 资料依据

本轮设计参考了当前项目已结构化的数据、里程碑评分规则、障碍评估、转衔评估、材料提示手册，以及各领域 DOC 任务分析表。后续已通过 macOS Vision OCR 识别上册指南和下册概况，详见 `upper-lower-ocr-analysis.md`。上册指南应作为逐项计分和测评逻辑主依据；下册概况应作为儿童记录本、多次评估、障碍/转衔表和任务分析追踪依据。

已经纳入结构化设计的资料重点：

- 里程碑评估共 170 项，16 个领域。
- 障碍评估共 24 项，0-4 分。
- 转衔评估共 18 项，1-5 分。
- 材料提示手册强调材料不是固定答案，需要结合孩子经验、准备多种材料，并说明评估结果。
- 命名、听者反应、视觉配对、LRFFC 等领域存在材料复用关系。
- 提要求、社会、游戏、教室常规、自发语音等领域大量依赖自然观察和计时观察。
- 下册每个项目有第 1 次至第 4 次评估格，历史对比应按多次评估快照建模。
- 下册任务分析和支持性能力约 900 项，应作为 IEP 和课程目标来源，不应被挤掉。

## 页面模板

当前 212 个项目被归到 18 类页面模板：

- `mand_event_recorder`：提要求事件记录
- `tact_trial_recorder`：命名试次/清单记录
- `listener_response_recorder`：听者反应试次记录
- `matching_trial_recorder`：视觉配对记录
- `play_observation_recorder`：独立游戏观察
- `peer_social_recorder`：同伴互动观察
- `imitation_trial_recorder`：动作模仿试次记录
- `eesa_subtest_recorder`：EESA 仿说分测试
- `timed_vocal_observation_recorder`：自发语音计时观察
- `lrffc_trial_recorder`：LRFFC 条件试次记录
- `intraverbal_response_recorder`：对话反应记录
- `group_routine_recorder`：教室常规/集体观察
- `language_sample_recorder`：语言样本/词汇清单
- `reading_trial_recorder`：阅读试次记录
- `writing_artifact_recorder`：书写作品记录
- `math_trial_recorder`：数学试次记录
- `barrier_rubric_with_behavior_log`：障碍评分和行为证据
- `transition_rating_with_auto_basis`：转衔系统建议和人工确认

## 提要求 1M 示例

`MAND_01M` 不是一个简单选择题。页面应记录：

- 本次使用的潜在强化物或活动。
- 孩子实际发出的词语、手语或图片交换内容。
- 要求的目标物或活动。
- 动机情境。
- 沟通形式。
- 是否使用仿说、模仿或其他辅助。
- 是否使用肢体辅助。
- 事件是否计为有效要求。

系统可以自动做的事：

- 统计有效要求数量。
- 按目标物或实际表达去重。
- 排除肢体辅助事件。
- 对照 1 分和 0.5 分标准建议分数。
- 将孩子原话和材料带入报告、Word、PDF 和 IEP 候选目标。

页面中间区域建议结构：

- 顶部：题号、题干、评分标准、素材准备提示。
- 左侧或上方：本题素材卡，显示已准备/已使用材料。
- 主区域：提要求事件表，提供“新增一次要求”快捷入口。
- 右侧：智能完成面板，显示有效数量、缺失条件、建议分数和需要老师确认的点。
- 底部评分区：固定在中间区域底部，但不遮挡事件表。

## 为什么每题页面会不一样

不是视觉风格完全不一样，而是“记录器”不一样。

同样是里程碑题：

- 提要求题要记录孩子原话、目标物、动机和辅助。
- 听者反应题要记录刺激组合、指令、目标、干扰项和孩子选择。
- 命名题要记录刺激物、孩子命名、材料形式和泛化样本。
- 书写题必须保留作品照片。
- 教室常规题要记录小组人数、持续时间、注意比例和破坏行为。
- 转衔题更多依赖系统汇总和老师覆盖原因。

因此 Pad 可以保持同一个头部、底部和整体风格，但中间区域必须按 `uiPattern` 动态变化。

## 智能完成规则

“智能”不应该只是提示。它至少要做到：

- 根据题项自动加载素材准备策略。
- 根据题项自动生成必填字段。
- 计时题自动开启计时观察结构。
- 泛化题自动生成矩阵。
- 试次题自动计算正确数量、正确率、组合大小。
- 清单题支持批量导入和抽样复核。
- 作品题保留附件并把作品证据绑定到评分。
- 障碍题汇总频率、强度、影响范围和高风险标记。
- 转衔题根据里程碑总分、障碍总分和重点领域自动建议分数。

老师仍然是最终确认者，因为 VB-MAPP 包含临床判断、孩子状态、材料适配和观察质量。
