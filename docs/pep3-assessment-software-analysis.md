# PEP-3 测评软件开发资料分析

> 分析范围：基于用户提供的 7 份 PEP-3 扫描版 PDF 做结构识别与开发拆解。PDF 多为扫描件，本文不转录完整题项、指导语、常模表或刺激图，只整理软件开发需要结构化的资料类型、评分链路、模块边界和风险点。

## 1. 资料分工

| 文件 | 软件开发用途 | 需要结构化的内容 |
| --- | --- | --- |
| `PeP3测试员手册 (2).pdf` | 施测资质、评核流程、计分解释、报告解释、常模附录、材料清单 | 评分规则、年龄计算规则、常模/换算表、解释等级、教育计划分析逻辑、物料清单 |
| `测试员记录册彩(1).pdf` | 测试员录入界面和结果汇总模板 | 儿童基本资料、13 个副测验汇总、项目评分矩阵、合成分数、剖面图、教育计划分析表 |
| `书写薄彩.pdf` | 书写/临摹类任务的纸面材料或平板任务页 | 书写页、临摹页、图形页、作答留痕/上传规则 |
| `照顾报告彩.pdf` | 家长/照顾者问卷 | 问卷题项、三类量尺、选项到分值的映射、备注字段 |
| `PEP-3测试用书(1).pdf` | 儿童端刺激材料 | 图卡、图片选择页、颜色/数量/场景刺激页、数字/文字页等资产 |
| `PEP-3常模(2025).pdf` | 当前常模换算的主要数据源 | 原始分到发展年龄、百分位、标准分、合成分的换算表 |
| `PEP-3使用册(1).pdf` | 每个项目的具体施测与评分说明 | 项目顺序、材料、指导语、评分标准、刺激页引用、书写薄引用 |

开发时应把 `PEP-3常模(2025).pdf` 作为当前计分引擎的主常模版本；手册中的旧附录可作为交叉校验或历史版本资料。

## 2. 测验结构

软件至少要支持 13 个副测验：

| 类别 | 代码 | 名称 |
| --- | --- | --- |
| 发展副测验 | CVP | 认知（语言/语前） |
| 发展副测验 | EL | 语言表达 |
| 发展副测验 | RL | 语言理解 |
| 发展副测验 | FM | 小肌肉 |
| 发展副测验 | GM | 大肌肉 |
| 发展副测验 | VMI | 模仿（视觉/动作） |
| 行为副测验 | AE | 情感表达 |
| 行为副测验 | SR | 社交互动 |
| 行为副测验 | CMB | 行为特征-非语言 |
| 行为副测验 | CVB | 行为特征-语言 |
| 照顾者报告 | PB | 问题行为 |
| 照顾者报告 | PSC | 个人自理 |
| 照顾者报告 | AB | 适应行为 |

合成分数建议按手册模型实现：

| 合成领域 | 包含副测验 |
| --- | --- |
| 沟通 | CVP、EL、RL |
| 体能 | FM、GM、VMI |
| 行为 | AE、SR、CMB、CVB |

PB、PSC、AB 在记录册中作为照顾者报告副测验展示，一般参与副测验层面的原始分、百分位、标准分和适应/发展程度输出；是否参与某个机构自定义总分，应做成配置，不要硬编码。

## 3. 评分链路

推荐把计分引擎拆成独立服务或独立包，避免前端重复实现规则。

1. 录入基本资料：儿童姓名、性别、出生日期、评估日期、中心/班别、测试员、备注。
2. 计算实际年龄：由评估日期减出生日期，保留年、月、日；手册强调不应随意四舍五入，常模查表按月龄/年龄段使用。
3. 录入项目分：发展和行为项目主要是 `2/1/0`；部分项目或副测验存在 `NA` 或未施测状态，必须与 `0` 分区分。
4. 汇总副测验原始分：按项目所属副测验求和，NA/缺失处理规则需按使用册逐项确认。
5. 换算发展年龄：使用“原始分与相应发展年龄”表，主要用于 CVP、EL、RL、FM、GM、VMI、PSC 等有发展年龄输出的副测验。
6. 换算百分位：使用“副测验原始分与相应百分比级数”表，按年龄段和副测验查表。
7. 换算标准分：使用“副测验原始分与相应标准分数”表，按年龄段和副测验查表。
8. 计算合成分：先把对应副测验标准分相加，再用“合成分数的标准分数与百分比级数”表换算合成标准分和百分位。
9. 生成解释等级：按手册/常模的“发展/适应程度”或描述等级生成结果文本。
10. 输出报告：包含副测验表、合成分数表、剖面图、照顾者报告、教育计划分析、备注和测试员签名。

照顾者报告的评分映射需要单独实现：

| 部分 | 选项结构 | 分值逻辑 |
| --- | --- | --- |
| 问题行为 PB | 无问题、轻微/中度、严重 | 2、1、0 |
| 个人自理 PSC | 三行能力描述 | 第一行 2、第二行 1、第三行 0 |
| 适应行为 AB | 三行能力描述 | 第一行 2、第二行 1、第三行 0 |

### 4.2 常模与规则表

| 表 | 关键字段 |
| --- | --- |
| `norm_versions` | `version`, `name`, `source`, `effective_date`, `is_active` |
| `norm_development_age` | `version`, `subtest_code`, `raw_score_min`, `raw_score_max`, `dev_age_month` |
| `norm_percentiles` | `version`, `age_band`, `subtest_code`, `raw_score`, `percentile` |
| `norm_standard_scores` | `version`, `age_band`, `subtest_code`, `raw_score`, `standard_score` |

常模表建议保留 `raw_score_min/raw_score_max`，因为 PDF 表中存在区间、`<`、`>`、空白或封顶/封底值；不要简单假设每个原始分都有独立行。

## 5. 功能模块拆分

| 模块 | 核心能力 |
| --- | --- |
| 个案管理 | 儿童档案、评估历史、机构/班级、家长信息 |
| 施测工作台 | 项目导航、材料提示、评分录入、跳题/暂停、未施测/NA、备注 |
| 快速录入 | 按记录册矩阵批量录入，适合纸笔施测后补录 |
| 照顾者问卷 | 家长手机端填写、测试员代填、进度保存、自动评分 |
| 常模计分引擎 | 年龄计算、原始分汇总、查表、合成分、等级解释 |
| 报告生成 | 记录册样式结果页、剖面图、教育计划分析表、PDF 导出 |
| 素材管理 | 测试用书图片、书写薄页面、材料清单、版本控制 |
| 质控审计 | 测试员权限、修改记录、计分复核、报告签发 |
| 系统配置 | 常模版本、术语语言、机构模板、隐私与导出策略 |

MVP 建议先做“纸笔施测 + 软件录分 + 自动计分 + 报告导出”。完整数字化刺激材料和儿童端交互可以作为第二阶段，因为题本图卡、书写页和实物材料涉及版权、清晰度和施测等值性。

## 6. 报告输出内容

报告至少应包含：

1. 基本资料：儿童、评估日期、实际年龄、测试员、机构。
2. 副测验分数表：原始分、发展年龄、百分位、标准分、发展/适应程度。
3. 合成分数表：沟通、体能、行为的标准分总和、合成标准分、百分位。
4. 剖面图：副测验标准分曲线、合成分柱状/表格。
5. 照顾者报告：PB、PSC、AB 原始分和解释。
6. 教育计划分析：按项目表现和发展年龄提取可训练目标。
7. 备注与签署：测试条件、儿童状态、异常情况、测试员签名/日期。

## 7. 资料数字化优先级

| 优先级 | 资料 | 原因 |
| --- | --- | --- |
| P0 | 13 个副测验定义、项目到副测验映射、评分选项 | 没有这些无法录分 |
| P0 | 2025 常模表 | 决定报告分数正确性 |
| P0 | 年龄计算和查表规则 | 常模结果最容易出错 |
| P1 | 记录册报告模板 | 决定临床/机构可用性 |
| P1 | 照顾者问卷 | 可独立做家长端和自动评分 |
| P1 | 使用册项目材料/评分说明索引 | 支持测试员施测工作台 |
| P2 | 测试用书/书写薄高清素材 | 数字化儿童端或平板施测需要 |
| P2 | 教育计划分析规则 | 增强报告价值，但依赖前面分数稳定 |

## 8. 关键风险

1. 版权风险：题项、指导语、刺激图、常模表和报告模板都可能受版权保护。商业软件上线前必须确认授权范围。
2. 扫描质量风险：当前 PDF 有旋转、阴影、裁切、低清晰度，不能直接作为生产素材。常模表尤其需要人工双录入和程序校验。
3. 计分正确性风险：年龄段、区间值、NA、未施测、封顶封底值都可能影响分数。计分引擎必须配测试用例，逐项对照人工记录册结果。
4. 施测等值性风险：PEP-3 包含实物操作、书写、图卡和互动观察，软件不应假设可以完全替代标准施测材料。
5. 临床责任风险：软件应定位为测评记录和计分辅助工具，报告需要合格测试员复核签发，不能自动给出医学诊断。
6. 版本风险：手册附录与 `PEP-3常模(2025).pdf` 可能不是同一常模版本，系统要支持常模版本号和历史报告锁定。

## 9. 推荐开发路线

1. 第一阶段：结构化项目库、照顾者问卷、记录册式录入、2025 常模计分引擎、基础报告。
2. 第二阶段：测试员工作台，按使用册显示材料提示、评分标准和当前项目进度。
3. 第三阶段：报告模板优化，加入剖面图、教育计划分析、机构盖章/签名和 PDF 导出。
4. 第四阶段：在取得授权和高清素材后，实现儿童端刺激材料、平板书写或拍照上传。
5. 第五阶段：质控体系，包括双人复核、修改留痕、常模版本迁移、数据备份和权限隔离。

## 10. 下一步需要补齐的数据

| 数据 | 建议处理方式 |
| --- | --- |
| 所有项目的编号、所属副测验、评分选项、NA 规则 | 从记录册和手册附录 6 建表 |
| 每个项目的施测材料、刺激页、书写薄页、评分标准 | 从使用册建立索引，不建议未经授权全文录入 |
| 2025 常模表 | 人工双录入或 OCR 后人工校对，生成 CSV/SQL，再用测试用例验算 |
| 报告解释等级 | 从手册解释章节抽象成规则表和模板 |
| 教育计划分析 | 以项目发展年龄和得分状态生成候选训练目标，由测试员确认 |
| 授权素材 | 使用正版电子资源或重新制作经授权的高清图卡/页面 |
